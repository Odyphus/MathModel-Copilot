# v0.2 架构选择与边界

本版从用户指定的 v0.1.3 继续开发。根 schema 4.0、copilot 子树 0.1 与领域对象含义保持兼容；没有新建前端业务数据库，也没有用 Git 历史替换 Store 的版本历史。

## 一个内核，两种只读入口

`copilot_view.snapshot` 为 CLI `view` 和 Dashboard 提供同一读取入口。它调用原有 `project_status`，在读取前后检查权威文件与登记文件的实际字节；同 revision 的磁盘变化仍会重新观察。连续变化时有界重试后报告冲突，不能把不同观测拼成当前事实。snapshot ID 用于追溯，不是身份认证或未来有效性的保证。

对象原始状态与当前有效性分别保留。失败、超时、缺输出的运行仍显示原失败身份；替换或文件漂移会使相关对象、已完成任务的输入输出和需求证据重新待核查。Stage 只作导航，覆盖比例有明确需求分母。历史记录不会因为当前已有替代品而被删除。

前端采用原生 HTML/CSS/JavaScript 和 Python 标准库服务，无需 Node 构建及前端依赖安装。这样清洁核心安装也能打开可选界面。服务固定本机，只有读取路由、精确静态资源白名单及登记文本读取；不提供状态修改、任意路径浏览或远程托管入口。登记文本按纯文本显示；请求核对当前 revision、权威字节和文件观测。

## 先研究、审查，再接真实数据

界面经过实际 Mobbin 参考研究，原创信息架构、线框和 Demo 高保真预设，以及独立 Agent 的两轮内部审查后接入真实观察层。完整来源与内部截图在独立设计证据包；发行代码不携带 Mobbin 截图或私有字体。内审不代表用户批准，CSS 视窗检查也不冒充原生浏览器缩放验收。

## Git 是可选的协作运输工具

默认 Local 不要求 Git 或账户。Git 适配器观察当前本地仓库事实，生成变更/影响说明、提案、交接和 PR 描述文件。离线本地引用不代表远程最新；子模块不会递归执行仓库配置，其未检查范围明确列出。

启用保护后，权威目录必须保持未跟踪，Store 的读取也检查这一约束。提案写回仍在原 Store 事务内核对项目、revision、state hash、对象依赖与文件绑定；不把 Git merge 的 JSON 当作可信业务事务。保护记录不保存另一份业务真相，也不提供针对任意本机文件管理员的认证。

复验分别报告当前采用对象与已经被替代的历史对象。正常替换留下的历史失效不应令当前绑定复验永远失败；复验通过也不等于 Submission Ready。只有换行字节差异而无行级 patch 时仍明确提示检查字节哈希。

## 发行与验收分开

新版入口独立命名 `mathmodel-copilot`。旧名兼容须显式选择，任何同名安装均拒绝覆盖。公开候选按源码白名单构建；原有官方题面、数据附件、内部研究截图及验收工作区保留在内部证据，不进入清洁安装包。

新增合成 MCM 示例使用同一 Runtime、独立 checker 和完整来源链，但只说明合成模型内的守恒与有限候选比较，不声称现场预测、全局最优或正式比赛通过。Windows/Linux、历史案例、独立角色接力、文档渲染与真人核验的证据范围各自记录。最终交付报告绑定候选文件哈希；本文件不预先声明尚未执行的测试成功。

未确认的迁入代码/新增派生材料许可、维护者身份和公开仓库仍是发行阻塞，因此交付 RC。没有自动公开仓库、push、合并 PR 或发布 Release。

## RC.2 本地工作台内容调整

依据用户讨论后的实现授权，将当前 Dashboard 定位于个人查看本机项目记录。保留权威内核和 Git 接力边界，暂不新增云端同步。主导航按进展、成果、论文组织；当前方案与人工待确认进入对应上下文；哈希、内部 ID 和原始状态只在诊断中保留。没有更改状态 schema、赛事规则、验证语义或现有文件 API。详细内容规则见 DASHBOARD_CONTENT.md。
