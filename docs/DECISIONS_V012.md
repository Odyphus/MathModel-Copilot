# v0.1.2 关键决定与验证边界

## 继续使用原状态与领域层

保留 schema 4.0 / copilot 0.1、Store 事务、不可变对象历史、Context 0.1.1 和既有交付状态。新能力是 Claim 的可选显示合同、PaperSection 的类型化来源/结构，以及 DeliveryAudit 内的来源回读报告；没有再建权威状态或独立 DocumentAudit 状态系统。

## 数字不以标签获得信任

结果仍从已核验 Result.metrics 重新计算绑定；类型、缓存绑定和外层哈希均不提供豁免。显示合同使用 Decimal 原值、精确 metric 路径、位数和舍入方式。非零舍入且出现明确比较/阈值时，相关原 Result 还必须含独立 checker 返回的完整结论。不能将另一 Result 的文字借给被舍入的来源。

结构数字仅在受限排版位置识别；年份、参数、公式和参考文献从当前版本字段或实际绑定注册表派生整块内容。不能提交任意忽略文本区间。数字、单位与科学计数法边界按同一规范化原则处理。

## 回读真正的最终文档

新来源/显示链必须提供 paper_source 合同。最终 DOCX 的段落顺序、表格格子、公式 token 和图片字节与登记来源比对；保留数字 token 序列，防止去空白把不同数值变成“相同文本”。不支持的可见容器、隐形文字和修订内容拒绝。Word 导出、PDF 页级审查、引用、AI 披露、完整源码附录和支撑 ZIP 继续使用既有检查器。

## 修复实测重复检查，不调整测试超时

旧 smoke 的原 240 秒门槛在本机两次超时。保留原失败后，cProfile 发现同一状态观察反复遍历公共祖先并重复读取文件。修复将完整对象检查复用限定在一次同步 observation 中；使用 ContextVar 按 authority 身份和根目录隔离，先拒绝 active cycle，检查全部完成才复用，退出或异常必清理。

没有按 revision 建长期缓存，也不跨独立读取、事务或宿主复用文件结果。下一次读取仍访问实际文件。负向测试覆盖相同 revision 的磁盘漂移、current/payload 变化、依赖环、跨根/跨 authority、异常清理和返回错误列表污染。独立对照核对了旧/新状态输出完全一致、读取相同的唯一文件集合、权威字节未变；具体测量条件和耗时保留在交付验证证据中，不据单样本宣称一般性能倍数。

## 历史验收不成为正式授权

新链选择与实际锁定规则对应的 AI 官方句式；旧生成器默认输出保留以兼容旧接口，其文字不被重新标记为官方合规。所有实际 AI 使用按账本披露，agent_evaluator 与 human 分开记录。历史 DeliveryAudit 即使通过，仍不会自动变成正式参赛、团队签字、上传完成或官方回执。

## 实际论文发现的迁移接口衔接

真实支撑清单包含官方题目原件名 `assets/Case_1_ result_E.xls`。旧公式源码检查器只理解无空格文件 token，因而把该文件名中的下划线误识别成未排版公式。没有扩大通用排除正则：仅当本轮有序来源回读及当前对象/文件核验通过，Delivery 才传递实际绑定文件的完整路径；公式格式检查只豁免附录内完全相同的“文件：路径”独占段落。正文、不同路径、前后追加内容与相邻公式继续检查。该内部参数不从 manifest 自报字段接收。

迁入 CitationAudit 的真实返回合同是 `hard_gate_status=PASS` 和 `status=READY`，原适配器却读取其不存在的 `passed`。修复只在原合同通过且非空 findings 中所有 error 项通过时设置 `passed=True`，保留 `migrated_status` 和质量 warning；错误引用、未核验来源与不完整报告仍失败。两项修复均有实际论文失败证据以及新增独立 DOCX 正负例，没有修改旧测试。

最终 Delivery 还暴露了同层 AI 检查对正文“见参考文献[2]”的错误截断。改为复用迁入 `ai_section_positions` 的独占段落标题识别，要求实际声明位于 AI 标题与参考文献标题之间。独立复核继续发现历史声明分类器中相同的旧字符串切分，也一并改为共享标题边界；引用提及后的相互矛盾声明不能再被截掉。正文提及不能充当标题，文后声明或其他位置的声明也不能补足该节。保留真实首次失败的 DeliveryAudit，并新增实际 DOCX 十项边界测试；不靠改写正常论文导航文字绕开问题。
