# 在本机逐项体验 MathModel Copilot

目标是回答两个不同的问题：**程序有没有正确执行；人用起来是否省心、能否形成自己的判断。** 不以自动测试通过代替后者，也不让体验者不断回复“继续”。本手册对应 README 的全部 13 项功能，另加下载安装，共 14 张验收卡。

## 怎样组织，才不用一直盯着 AI

先建立一个独立验收目录，把试用安装、练习项目、过程记录放在分开的子目录。不要使用正在参赛的项目做篡改、冲突或失效试验。个人数据测试目录必须位于项目和 Git 工作树之外，不能混进队伍仓库。

分三段推进：

| 一段体验 | 包含什么 | 人集中看什么 |
|---|---|---|
| 开始与选型 | 下载安装、教学、审题、候选模型、歧义与假设 | 第一轮讲解原文；两个方案是否真有差异，专业术语是否准确 |
| 运行与变化 | 真实计算、独立检查、结果依据、参数修改、工作台 | 哪些数字有依据；回来时能否立刻看懂变化和下一步 |
| 收尾与接力 | 论文图表、交接、赛事交付、复盘、经验、反馈 | 材料是否方便人继续写作；新会话能否接上；反馈是否准确 |

AI 可连续完成授权范围内的程序操作，每段留一份短报告和原始证据。普通实现无需逐步询问；只有影响建模方向的实际选择、外部分享或缺少必要权限时才集中处理。你可以等一段结束后再看，不必守着聊天。下一次先读取验收记录，不要求你重新回忆。

**先看默认表现，再看显式调用。** 例如第一轮只说“用 MathModel Copilot 帮我做这道练习题”，不要先用长提示把所有标准塞给它。记录它是否主动分析、比较方案、解释功能；随后再用验收卡里的短句检查指定入口。这两轮不能混成“默认体验已通过”。

## 固定材料

对话部分可用下面这道原创小练习，不必一上来完整做数天的比赛：

> 某园区有 4 个连续一小时时段。负荷功率依次为 2、4、3、1 kW，光伏可用功率为 0、1、4、0 kW，购电价为 0.5、1.2、0.8、0.4 元/kWh。储能容量 3 kWh，充、放电功率上限均为 2 kW，充、放电效率均为 0.95，初始和结束电量均为 1 kWh。允许弃光，不允许向电网售电。第 1 问：设计购电与储能调度，降低总购电费用，写清约束和结果检查。第 2 问：将容量改为 2 kWh，比较影响。第 3 问：讨论光伏预测有误差时，原方案有哪些局限，需要怎样验证改进思路。输出各时段调度表、总费用和必要的说明。

这是合成练习，不是任何比赛的官方题目，也不预先规定唯一最优数值。先让 AI 比较可行方案；不得拿仓库中的合成交通结果冒充本题结果。候选例如 LP 与离散状态动态规划是否适用，应由模型假设、离散误差和约束决定，不能机械要求列满几个术语。

程序链快速核对则复用包内**合成交通示例**及原来的参数变更脚本。它和上述对话题是两个独立案例，证据分别存放：前者帮助检查系统行为，后者用于观察建模讲解。不要为了统一进度把两个项目的结果相互登记。

## 14 张验收卡

### T00 · 下载与安装

点击 README 的“快速下载 Skill”，在浏览器下载记录中确认拿到 ZIP，而不是跳到源码文件页。把 ZIP 发给 AI，只说“安装这个 Skill，然后告诉我怎样开始”。在独立目录试装，确认只出现一个主入口。再次向同目录安装时应拒绝覆盖，原内容保持不变。

保存下载来源、实际版本、安装位置、入口截图或列表，以及是否需要额外解释。按钮、下载文件和安装分别记录；API 下载成功不能代替浏览器点击成功。私有仓库没有访问权限时的 404 不应归为压缩包损坏。

### T01 · 随时教学（README 1）

先跳过首次介绍，随后说“进入教学模式，只讲怎样比较模型”，再说“退出教学，回到刚才的题目”。工作台也走一遍“使用帮助 → 单项主题 → 返回”。

应能重新进入、只讲所选主题，退出时回到原任务；读取帮助不初始化项目、不登记结果、不替你授权留存。检查内容是否真的指导下一步，而非堆功能名。保存对话原文与页面截图。

### T02 · 完整审题（README 2）

将上面固定练习交给 AI，先用最简请求观察默认表现。应识别 3 个小问、调度表与费用等输出、kW/kWh 的关系、边界电量、弃光和不售电条件，以及第二问对第一问的依赖。

将它生成的要求清单逐条与题目对照，这是审查是否漏登记的步骤；另外保留已经登记的要求，故意不生成或不关联其中一项输出，程序应仍显示缺口。程序不能仅凭清单证明清单自身没有漏项。保存题目副本、首轮回复和清单；登记成功不计作求解完成。

### T03 · 候选模型比较（README 3）

先观察默认是否比较路线，再单独说“给我两个可比较的方案”。检查每个方案的专业名称、变量、目标或方程、假设、算法、验证方式及代价；能否据此作出选择。不是两个名字不同、内容相同的方案。

把“只讲直觉”“只有术语”“将算法错当模型”“未运行就报结果”分别记录。无合理第二方案时，应说明原因。记录是否查阅外部资料及实际来源；与网上方案相似本身不能证明受到干扰。

### T04 · 题意歧义与假设（README 4）

在独立副本中把“初始和结束电量均为 1”改为“初始和结束电量相等”，让 AI 解释两者差异并列出候选解释。不要把这一改动偷偷带入原练习。

应识别固定值与自由初值可能导致模型、结果不同；未处理的高影响歧义不应被当作已解决。选择一种解释后，再查看实际登记的决定及影响范围。记录只是决定，不等于数学已验证。

### T05 · 真实运行与独立检查（README 5）

让 AI 按选定方案运行，先明确检查标准。查看实际进程返回、结果表、运行记录和独立检查报告。合成交通程序演示也可以快速核对此链路。

在独立负向测试中制造一个约束不满足或缺输出的结果，检查是否被拒绝。不能把同一段计算复制两遍就称独立检查；不能以“PASS”文字代替报告和真实文件。记录失败、缺依赖、跳过、未执行的具体类别。

### T06 · 依据与变更失效（README 6）

先有一轮真实有效结果，再改变已登记参数，暂不重跑。查看旧结果、结论和章节是否需要重检；随后实际复算、检查并关联新结果。

应保留历史，新结果可用不自动让旧论文段落通过。使用下方交通演示脚本可观察 5/5 → 0/5 → 5/5，最后旧章节仍需重检。保存三个时点的状态和对应文件，不手改权威 JSON。

### T07 · 工作台（README 7）

打开四个主入口，看完一批变化后记为已读；后台进行 T06 的参数变更，再回到页面。查看是否出现新变化、受影响成果和下一步，刷新是否保留阅读位置。

人实际判断中文是否清楚、关键结果能否找到、内部编号是否影响阅读。可选交互模式只保存一条建模意见，应显示已保存，而不是已采用或已核验。AI 唤醒另记：未真实返回就不标通过。保存截图和浏览器错误，避免只看源代码。

### T08 · 论文、摘要与图表（README 8）

基于真实结果说“整理材料和论证提纲，推荐必要的图表并说明理由，再列出摘要要点”。观察是否用专业模型术语、已验证数字和适用条件支撑建议，是否解释图表与论证的关系。

提供一张故意绑错小问或参数的 CSV，机械预检应报不一致；这不等于检查成图或全文语义。本人判断提纲、图表取舍、摘要重点是否有用。原稿不得被覆盖；任何排版验收要实际渲染并逐页查看，缺工具标为未验证。

### T09 · 接力与 Git（README 9）

从同一项目生成建模、编程、写作三个角色的交接材料，在新的会话中读取其中一份。应与当前模型、结果、缺口一致；收到、采用、核验分开。

可选 Git 用两个本地副本从同一基线生成两份修改同一参数的提案，在同一个权威端先采用第一份，再尝试采用第二份，或使用旧 expected_revision 再次写入；冲突应被拒绝，Git 合并不能直接授予有效状态。两个独立副本各自接受本地修改，本身不代表冲突机制失效。此模拟不证明真实三人云端同步；真正队内体验仍需不同操作者参与。不要为了这个测试自动推送比赛资料。

### T10 · 赛事、复核和交付（README 10）

在练习模式核对赛事配置、规则来源、交付清单和 AI 使用记录，让 Critic / Red Team 指出至少一项真实的未验证假设或论证缺口，不为凑问题编造错误。

故意缺少一份要求的材料，应仍不具备待提交条件；历史演示即使计算检查通过，也不能成为正式可提交。实际比赛的最新官方规则须另行核对。人工终审和正式提交不能由测试脚本代签。

### T11 · 复盘与新会话续接（README 11）

先明确“本次可保存关键过程，只在本机使用”，完成一段工作后自然地说“今天先到这里”。观察 AI 是否生成可实际打开的 Markdown 复盘，而不是只回复“记住了”。在新的会话中给同一项目目录并说“继续上次的项目”。

应能回顾取舍、未完成项并重查当前文件。再用独立副本测试源文件变化，旧复盘成功不应掩盖当前失效。记录是否需要额外提示；手工调用 recap/resume 成功与 AI 自然触发成功分别评分。真正的新会话尚未发生时保持待验证。

### T12 · 偏好与选定经验（README 12）

明确保存一条讲解偏好，以及带适用条件的单位经验；在第二个独立练习中检查是否读取且说明条件。随后撤回该经验，再次读取应排除它。

没有跨项目授权时不读取；不符合标签或来源失效时不套用。检查个人记录没有进入比赛项目的 Git。界面或命令显示偏好存在，不等于 AI 的后续表达已经遵循，后者看实际回复。

### T13 · 使用反馈（README 13）

选一次刚才真实发生的困惑，让 AI 组织“目标、预期、实际、相关过程、纠正、后续、缺口”，先生成草稿并导出 Markdown。检查脱敏后是否还保留足够上下文；没有聊天原文时必须标为转述。

本地记录授权不等于分享授权。真正发送前展示精确正文、仓库、账号和可见性，取得对应授权后再发；记录实际 Issue 链接并回读。未授权发送、无账号或无权限时保留本地。外部真实送达未执行就保持待验证；维护者是否复现又是后续状态。

## 可直接复用的程序演示

这些命令面向执行 AI 或维护者，普通用户无需手填；在仓库根目录运行。每次选择新的 `trial-project` 和 `trial-evidence`，不要覆盖旧验收。演示目录放在源码之外。

```sh
python scripts/copilot.py --workspace ../trial-project demo --horizon 12
python scripts/copilot.py --workspace ../trial-project status
python scripts/copilot.py --workspace ../trial-project experience tutorial --topic models
python scripts/copilot.py --workspace ../trial-project dashboard --port 8765
```

最后一条保持服务运行。在另一个终端从同一仓库根目录执行，先观察参数变化，再复算：

```sh
python docs/demo-preview2/evidence/extend_demo.py . ../trial-project ../trial-evidence change
python docs/demo-preview2/evidence/extend_demo.py . ../trial-project ../trial-evidence rerun
```

12 秒只是小型集成演示，不能标为原版 600 秒演示。原脚本通过正式 Runtime 事务变更，不直接编辑状态。查看其他角色、复盘、经验和反馈的具体入口时先读 `--help` 或 [执行协议](../references/experience_runtime.md)，不要猜字段。

需要程序回归时复用既有测试，避免再写一套与产品平行的测试系统：

| 验收范围 | 可选的既有测试文件 |
|---|---|
| 安装和单入口 | test_install_v020.py、test_install_sync_rc4.py |
| 合同、要求与解释 | test_problem_contract_rc3.py、test_preview_interpretation.py |
| 真实运行、依据、失效 | test_copilot_runtime.py、test_examples_v020.py、test_claim_v011.py |
| 工作台 | test_dashboard_v020.py、test_tutorial_dashboard.py、test_dashboard_*.js |
| 论文预检与输出 | test_beta_paper_review.py、test_render_guard.py |
| 角色交接与 Git 冲突 | test_context_v011.py、test_git_v020.py |
| 交付与规则 | test_copilot_delivery.py、test_ai_declaration_v012.py |
| 个人复盘、经验、公共 CLI | test_copilot_experience.py、test_experience_guidance_contract.py |
| 反馈脱敏、发送失败及去重 | test_copilot_usage_feedback.py、test_copilot_experience_redteam.py |

例如选一组运行并保存实际结果：

```sh
python tools/run_regression.py --pattern test_experience_guidance_contract.py --output ../trial-experience-checks
```

测试会自建隔离夹具；测试用合成授权不代表实际用户已同意。离线发送替身不算真实 GitHub 投递。首次安装维护依赖时按 [安装说明](INSTALL.md)操作；缺依赖、代码失败、主动跳过都保留，不为清零跳过项修改断言。

## 每项怎样记结果

每张卡保存：版本与宿主、输入材料、实际操作或提示词、预期、观察到的行为、证据路径、补充提示次数、实际耗时（能测才填）和下一步。不要完整复制全部聊天，只保留本次获准且必要的材料。

| 字段 | 允许的结果 |
|---|---|
| 程序行为 | 通过 / 失败 / 环境阻断 / 未执行 / 不适用 |
| 默认 AI 行为 | 达到预期 / 补充提示后达到 / 未达到 / 未执行 |
| 人的体验判断 | 本人原话 / 待本人体验；AI 不代填满意 |
| 外部动作 | 未请求 / 未授权 / 未执行 / 结果未知 / 回读已送达 |

一轮结束，先修复证据足够的问题，再重跑对应卡。未复现的反馈保留为线索。README 配图从实际验收取材，注明版本、是否合成输入和未验证边界；不能用界面预设或准备好的解释稿冒充真实 AI 表现。
