# MathModel Copilot v0.1 实施与验收记录

基线：`handsomeZR-netizen/mathmodel-skill`，`e0e65c8c56f1f0435fb76e99490dbae7c2704d59`。
需求来源：用户提供的 Copilot 功能文档 v1.0、复现与拆解报告 v1.1、cumcm-workflow 1.6.0 功能文档；文档中的历史授权不自动扩大本次授权。

## 范围与完成判据

保留上游 Stage 0–9、按问迭代、Critic/Red Team、初始化、只读状态和论文装配。迁入既有领域对象和检查器；新增需求、任务、执行、协作 Context 和规则锁。首版通过功能文档七个负向/恢复场景及一道真实旧题。发布、安装、正式参赛提交不属于本次本地开发。

## 内部检查点

1. **基线**：原测试与报告风险隔离复现，记录版本、失败和跳过。
2. **状态**：单写入口、原子事务、版本冲突、幂等、嵌套结构与只读恢复；真实双进程测试。
3. **领域/任务**：迁入对象、Requirement Matrix、Task 依赖、真实 Run 与验证、EvidenceMap、跨问 Impact；新输出/失败/超时/过期负向测试。
4. **协作/交付**：三角色共同事实、累计变化、接收/采用/核验；持续论文、规则锁、文件版本与提交审计。
5. **总验收**：旧题重新执行、独立 Red Team、原回归、包清单/哈希/独立解包检查与功能完成度报告。

每个检查点通过后自动继续。测试结果在交付报告与 evidence 中记录；未执行检查不会被计为通过。

## 关键设计决定

- **ADR-001 单一权威**：保留原 `state/decision_log.json`，新增 `copilot` 子树。所有程序写入调用 `Store.transact`；不运行旧 `.cumcm` 状态写入器，不建数据库。规则锁、Context 和状态看板均为该状态的投影或版本绑定附件。
- **ADR-002 并发边界**：支持同一权威本地文件的多进程，通过操作系统文件锁 + 乐观版本比较提交。锁随进程结束释放；不声称提供云盘或多机分布式事务。
- **ADR-003 证据语义**：对象正文不可覆盖，新版本取代旧版本并沿依赖传播 stale。评分只表示建议；完成、可引用与 Ready 必须检查实际文件、运行回执和验证。
- **ADR-004 迁移而非重复实现**：从用户提供的 cumcm-workflow 提取对象、纯校验和文档检查，保留字段与来源；原状态 writer 不迁入。新执行器只补充原 `run register` 没有的真实执行回执。
- **ADR-005 历史结果**：旧记录保存且显式标为 legacy/unverified。迁移不会凭旧 pass 自动造出新 Run、人工签字或正式结果。
- **ADR-006 宿主**：文件/执行能力以实际探针报告，账号、网络服务、Word、并行 Agent 等未实测项保持 unknown。缺少能力只阻断依赖它的操作。
- **ADR-007 规则与年份**：problem_year、rules_year、evaluation_mode 分离；Competition Pack 保存来源与基线，项目锁保存实际采用版本，包存在不等于团队已核验当届规则。
- **ADR-008 交付状态**：generated、checked、frozen、awaiting_submission、submitted、receipt_received 分开。工具不自动执行外部上传，正式人工确认必须有具体版本和来源记录。
- **ADR-009 当前对象范围**：每个小问、每类源契约使用一个稳定 key，所有变更创建同 key 新版本。候选比较写在模型候选/实验配置内；不能换个 key 绕过旧版本失效。跨问输入显式绑定 Result；完成覆盖必须对应模型实际声明的具体 ReqID，不能仅凭依赖闭包中出现题意文件。
- **ADR-010 运行和数值绑定**：执行入口与 checker argv 均在运行前锁定；运行副本、参数上下文和原始源文件共同检查。数字主张匹配已验证 metrics 并保存绑定，不能因此声称自然语言推论、因果或全局最优已获得机器证明。

## 已知验证边界

目标环境是本次 Windows/Python。原 TeX、Office 及跨宿主能力以实测为准；发现缺少组件时保留失败/未执行证据，不以替代预览冒充原渲染成功。
