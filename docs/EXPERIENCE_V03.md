# 0.3 Preview：用得明白，下次接得上

把用户运行包交给能操作本地文件的 AI，说明“安装并使用这个 Skill”；如果已有版本，先用独立目录体验，安装器不会覆盖旧版。接着给题面和附件，或者直接说“进入教学模式”。不用先学命令，也不用填完功能菜单。

## 随时进入教学

第一次使用可先了解功能，也可以直接开始。以后任何阶段都能说：

> 进入教学模式，只讲一下怎样比较模型和检查结果。

工作台“使用帮助”提供同一套 12 项主题。关闭首次提示不影响再进教学；退出后回到原页面，AI 重新读取当前项目再继续。网页只复制请求时会说明还要发给当前 AI，不假装已经唤醒聊天。

## 允许记录以后，收尾不必再手动总结

> 本项目可以记录关键取舍和遇到的问题，结束后整理本次复盘，下次帮我接着做；先不对外分享。

这会把本项目的过程留存、收尾和续接一起说明并记录。只想试一次，可以说“只保存这一次”。没有同意时照常建模，不额外归档聊天。保留的是必要片段、来源和缺失说明，不是全量宿主聊天；AI 转述与逐字文件片段分别标注。

本段工作完成、交接或明确结束时，执行 Skill 的 AI 生成本地 Markdown：当前可用结果、关键取舍、困难、未完成事项和下一步。文件经回读后才报告保存成功。强制关掉宿主后没有后台运行保证，下次从已保存部分恢复。

## 回来后先重查，再继续

> 继续上次的项目，先告诉我现在什么仍然有效。

AI 读取旧复盘来理解取舍，再读取权威状态和文件来确定当前事实。即使项目版本号没变，代码或数据修改也会触发重查。旧成功不会覆盖当前失效结果。

> 以后讲解保留专业名称，同时解释清楚。把我选中的这条单位换算经验留给类似题目参考。

使用偏好和跨项目经验要另行明确选择。经验带来源、标签和适用条件，只读取少量相关项；撤回、来源缺失或失效会被排除。不会自动把旧题假设套到新题。可以随时让 AI 查看、修改、关闭复用、撤回或删除选定个人记录。

## 反馈可以具体，又不用重写全过程

> 把刚才“方案太简短”的问题和那两段相关过程整理成使用反馈，写清我想要什么、实际发生什么、后面怎么处理，再给我看准备分享的正文。

系统重新选取必要材料，区分程序事实、用户感受和 AI 推断，并标明哪些上下文缺失。原文拿不到就不编造。反馈草稿可以编辑或跳过；初始化失败也能反馈。

分享分三种选择：不分享、看过具体内容再提交、明确授权后自动分享限定信息。最后一种只包含版本、系统类别和本地体验记录概况，不包含自由文本、题目、结果和聊天。它适合了解使用路径，不能替代详细的问题反馈。

发送需要实际接收仓库和 GitHub 账号；会展示仓库、可见性、账号与完整正文。远端内容回读一致才显示送达；网络结果未知先核对，缺账号或仓库留在本机。公开 Issue 使用实际账号，不承诺匿名。详见 [反馈操作与边界](USAGE_FEEDBACK.md)。

## 页面与自动化边界

工作台仍是固定页面，不为每道题重新制作。默认只读，教学和复盘读取不修改项目；建模意见、额外 AI 分析与 Git 接力仍按需启用。页面关闭首次介绍的偏好保存在本浏览器，对话侧明确保存的个人设置存产品用户目录，两者不会悄悄互相覆盖。

个人记录位于本机用户目录，和比赛项目分开，不自动进入队伍 Git。Windows 使用用户目录访问权限；其他平台创建仅本人访问的目录。路径隔离和校验不意味着加密，也不抵御本机管理员。当前 AI 若在云端运行，整理记录仍使用该宿主，不能称为完全离线。

本 Preview 保留旧建模流程、真实运行、证据、论文与提交检查。个人记录不会把题目要求改成“已核验”，论文仍由人主导。软件回归、真实浏览器、真实 GitHub 送达、不同宿主和真人首次体验分别验收，以本次交付报告为准。

维护者的命令与输入示例见 [执行协议](../references/experience_runtime.md)。
