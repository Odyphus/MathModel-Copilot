# RC4：内测建模表达与论文辅助修正

## 设计决定

- FB002：保留通俗引导，方案输出明确专业模型、数学结构、求解算法、选择与验证状态。修改 Stage 3 的说明卡；不强行添加未实现机制或高级术语。
- FB003：主动比较图/表/数值的论证价值，说明适配、来源字段、边界和成本；定量图仍由真实数据生成。本版不加入自动生成式科学图像，也不承诺审美评分能证明科学质量。
- FB004：摘要先依据当前已核验结果形成材料/提纲，用户需要时给候选稿。提供可追溯案例接入模板；没有新增已审核论文语料库，没有收集或再分发未知授权的优秀论文。
- FB007：论文由人主导；默认交付写作材料和批注，保留原稿。新增机械预检以暴露来源错配、表格缺列和非有限值等可自动发现的问题。

## 实现与既有能力的边界

原有 `claim_evidence_errors` 已检查运行所属小问与 Requirement，`object_errors` 已检查当前版本、文件与上游依赖，DOCX 回读已核对登记章节及图片字节。本次不重复实现或放松这些规则。

新增 `scripts/copilot_paper_review.py` 复用 Store、object_errors、safe_path 和文件绑定。合同用于声明材料的预期使用位置：小问、实际 Result、ParameterSet 对象、来源对象、CSV 路径、必需列和数值规则。脚本重新读取权威状态与文件，比较真实 RunRecord 和参数依赖；筛查实际 CSV 和 Markdown/TXT，不仅匹配提示词文字。

CLI 退出码：0 为声明材料的机械检查通过；1 为发现不一致/缺失/非有限值等；2 为输入或合同错误。标准输出为 JSON。脚本只读，不改变状态，不把材料或章节标 verified，也不改变 submission_ready。

合同数值规则可用 `min`/`max`，两者均须有限并保持顺序；`unit`、`basis` 必填。`missing` 为“可读占位文本 → 明确原因”映射，不允许把 nan/inf 列入允许清单。没有题意或物理依据时不要捏造范围。检查全部非有限数值不受列是否在 numeric_columns 中的影响；普通字符串列不会因包含 banana 等词误报。

## 可复跑测试

```bash
python -m unittest discover -s tests -p 'test_beta_paper_review.py' -v
```

测试先建立真实 Runtime 项目，执行标准库合成求解器、运行独立 checker 并生成 ResultRecord，再使用正常登记的派生表制造失败。覆盖：

1. 已实际运行并验证的正例；检查前后权威状态字节不变。
2. 同一数据表用于另一小问、参数身份替换、派生表未绑定 Result。
3. 漏表面列、时间值误入温度列、nan/inf/Unicode infinity/数值溢出/空值/坏值。
4. 有理由的几何缺失标记；nan 不能通过允许列表绕过。
5. 重复表头、行宽错误、无数据、无检查项和错误合同。
6. 同 revision 文件漂移、上游代码漂移、同内容但未绑定路径。
7. 正文 nan 筛查及普通英文词避免误报。
8. CLI 非零结果和不写权威状态。

## 仍未验证/不声称解决

- 合成反例证明机械检查能发现这些类型的错误，不是重新求解用户 A 题。用户原件和旧 ZIP 没有改动。
- 仅覆盖明确声明的 CSV 与 Markdown/TXT；不自动解析 Excel、查出所有未声明图表或检测正文任意语义的跨问挪用。派生 Artifact 的依赖是声明来源，检查不能代替独立复算转换程序。
- 范围/单位依据需要内容复核；“数值位于范围”不证明单位标签或模型正确。脚本不检查实际绘图字段代码与图片像素、字体、裁图、PDF 页数。
- 没有伪造作者确认，没有做真实用户摘要写作质量或通俗专业表达的盲评；相应行为指令和模板需要后续真实内测验证。
- 真实 DOCX/PDF 继续走既有来源回读、渲染、逐页与人工最终审查；不能用本次预检通过替代完整论文验收。
