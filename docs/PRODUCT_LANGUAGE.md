# MathModel Copilot 产品术语与文案规范

更新：2026-10-07。本文统一产品界面、AI 对话、使用说明与对外介绍中的名称。它是命名规范，不是功能验收或发布声明；实现情况仍以当前代码和实际验收记录为准。

## 产品是什么

**MathModel Copilot：面向数学建模比赛的 AI 建模助手。**

它以 AI 技能包（Skill）的形式使用，帮助队员与 AI 持续推进审题、方案比较、建模、计算、检查、论文准备和任务交接。系统整理进度、版本和依据，队员负责重要判断、取舍和论文定稿。

- 品牌名固定为 **MathModel Copilot**，不另造多个中文产品名。短说明可用“数学建模助手”。
- 用户首次接触 Skill 时写“AI 技能包（Skill）”；后文用“技能包”。安装标识 `$mathmodel-copilot`、目录名和命令保持原样。
- Dashboard 的产品名称统一为 **建模工作台**，上下文明确时简称“工作台”。含义是查看本机项目、成果、待处理事项并继续工作的页面。
- 工作台是产品的一部分。名称不代表三人已在线同步，也不代表页面能够直接唤醒现有 AI 聊天。

## 工作台入口

保留既有四个主入口，不为术语调整另做一套页面或导航。

| 名称 | 用户来这里做什么 | 不应混入的含义 |
|---|---|---|
| 项目总览 | 看整体进展、最近变化、待判断事项和下一步 | 不显示由阶段数推算的“比赛完成率” |
| 各问进展 | 看每一问的要求、当前方案、参数、任务和结果 | 有方案不等于已运行，有结果不等于全问完成；候选比较目前在 AI 对话中进行 |
| 成果与依据 | 看计算结果、论文结论、图表文件及其来源和检查记录 | 来源对应不代表数学论证已成立 |
| 论文准备 | 整理章节材料、结论依据和提交前缺项 | 不是“一键完成论文”，材料齐全不代表作者已定稿 |

“当前方案”“题目要求清单”等内容继续放在相应小问中；诊断信息按需导出，不增加“对象管理”“版本管理”等普通用户不需要的一级入口。

## 功能与记录名称

左列供维护者定位原概念，中列用于中文界面和对话。代码、命令、接口字段、文件路径保持兼容，不按此表批量重命名。

| 内部或旧称 | 统一产品名称 | 定义与用法 |
|---|---|---|
| Workspace | 建模项目；项目文件夹 | 讨论工作整体叫“建模项目”，说明文件位置叫“项目文件夹” |
| Stage / Workflow | 工作阶段 / 建模流程 | 用“审题”“方案比较”等具体阶段名引导；阶段只表示位置 |
| Requirement Matrix | 题目要求清单 | 各问必须回答的问题及应交付的输出 |
| Requirement | 题目要求 | 清单中的一项，不以一个小问替代全部细项 |
| ProblemContract | 题意与交付要求 | 对某问输入、输出、约束和解释口径的完整约定；区别于单项题目要求 |
| Ambiguity / AmbiguityEntry | 题意解释 | 记录题意的不同解释及取舍；只有尚未确定口径时才列为“待明确的题意”，已记录的选择与依据变化后的重检分别说明 |
| Assumption | 建模假设 | 为建立模型采用的前提；采用假设与检查假设分别记录 |
| ModelSpec | 模型方案 | 模型名称、数学结构、假设、输入输出及检查方法 |
| ParameterSet | 参数设置 | 当前采用的参数取值、单位和来源 |
| Data Contract / DataContract | 数据说明 | 数据来源、字段、单位、处理方式及检查要求；这份说明本身不证明数据正确 |
| Task / Task Runtime | 任务 / 任务执行 | 要做的工作及其实际执行情况；展示具体任务名 |
| CodeManifest | 计算代码 | 本次模型计算所使用的代码及版本记录 |
| RunRecord | 计算记录 | 一次实际运行的输入、环境、输出与结束情况 |
| ValidationPlan | 检查方案 | 运行前声明要检查什么、通过条件和适用范围 |
| ValidationReport | 检查报告 | 实际执行上述检查后留下的结果与依据 |
| ResultRecord | 计算结果 | 一次运行产生、与检查记录关联的结果 |
| Claim / EvidenceMapEntry | 论文结论 | 需要写进论文并有来源支撑的一项表述 |
| EvidenceMap / Provenance | 结论依据 / 来源记录 | 前者说明结论由哪些结果支持；后者说明数据、模型、文件的来源 |
| ArtifactRecord | 附件 | 已登记的相关文件；仅确为成果时称“成果文件”，不能把所有附件称为成果 |
| Impact | 变更影响 | 修改数据、模型或参数后，哪些结果与材料需要重做或重检 |
| Task Context | 任务交接说明 | 根据当前项目记录整理的目标、进展、依据、待办和交接范围 |
| report / 事实简报 | 项目进展简报 | 当前时刻的可分享进度记录；不是全过程复盘，也不是参赛论文 |
| Competition Pack | 赛事配置 | 某赛事适用的流程、格式和规则检查资料；不暗示当届规则已核实 |
| Host / Host Adapter | AI 工具 / AI 工具适配 | 前者是运行技能包的工具；后者描述接入能力。用户操作写“连接 AI 工具” |
| Critic / Red Team | 方案评审 / 反例检查 | 审查方案或寻找失败情形；评审建议和评分不代替实际检查 |
| PaperSection | 论文章节 | 论文的一部分，来源核对与内容审阅分别进行 |
| DeliveryAudit / SubmissionAudit | 提交材料检查 | 对具体文件、格式、规则和缺项的检查 |
| DeliveryPackage / SubmissionPackage | 提交材料包 | 拟交付的文件集合；生成包不代表已提交 |
| Git collaboration | 队内交接（可选 Git） | 利用 Git 传递记录、提案和文件；接收与采用仍按原流程检查 |

专业模型与求解方法不改成模糊昵称。首次写“混合整数线性规划（MILP）”“有限体积法（FVM）”并解释作用，后文可用缩写；模型、求解算法和软件库分别说明。单位、数学符号和真实数值保留。

## 三种信息往哪里去

| 名称 | 对象与用途 | 当前边界 |
|---|---|---|
| 建模意见 | 队员向 AI 提出当前题目的想法、疑问和建议 | 已有本地记录入口；可选 AI 分析的接通程度按实际环境判断 |
| 项目进展简报 | 自己或队友了解当前已登记进展 | 已有 `report`；生成简报不自动发送，也不自动同步队友项目 |
| 使用反馈 | 用户向产品开发者报告使用经历、问题或建议 | 由独立 `usage-feedback` 处理；现有 `copilot.feedback` 仍只是题目的建模意见，不能混用 |

个人记录中的“本次复盘”是给用户回顾使用过程的总结；“使用反馈”是用户选择对外分享的部分。二者须分别说明收集范围和缺失内容。GitHub Issue 首次可写“反馈记录（GitHub Issue）”，提交按钮用“提交使用反馈”。对话侧发送器保留草稿、已审阅、结果未知、已送达等状态；只有远端内容回读一致才是已送达。页面使用帮助提供操作引导，不直接发送。

## 状态必须说明检查了什么

保留既有状态机，只统一表达。内部 `verified` 不直接翻成无范围的“已验证正确”。列表里可使用“已检查”这个短标签，但必须显示对象类别，详情说明检查范围。

| 场景 | 对外表达 | 成立所需依据与边界 |
|---|---|---|
| 保存建模意见 | 已记录；尚未发送给 AI | 本机保存成功；不能写成“AI 已收到” |
| AI 分析结束 | 已回复 | 收到有效回复；不表示方案已采用或结果已检查 |
| 收到队友材料 | 已收到更新 | 已登记接收；还没有因此采用该方案 |
| 采用方案或解释 | 已采用；采用了什么写明 | 存在采用记录；不据此推断人工身份或数学正确性 |
| 完成计算 | 已运行，待检查 | 程序实际运行成功；不表示独立检查通过 |
| 计算结果核验 | 已检查；详情写明本次计算及配套检查范围 | 有当前有效运行、检查与来源；不扩展为科学结论或全局最优证明 |
| 题目要求核对 | 本问要求已核对 | 该问全部当前要求有有效覆盖；不等于论文完成 |
| 论文结论或章节核对 | 已检查；详情写明“结论来源已核对” | 不能简称“论文已通过”；来源对应不替代论证、单位和作者审阅 |
| 文件或上游变更 | 需要重新检查 | 当前材料依据发生变化；保留旧版本供追溯 |
| 曾用但已被替代 | 旧版本 | 不把所有历史记录都变成当前阻碍 |
| 材料审计通过 | 已完成材料检查 | 只代表这次材料检查范围；仍需核对实际提交条件 |
| Ready | 已具备待提交条件 / 正式提交条件尚未满足 | 来自当前提交检查；不用笼统“全部完成” |
| awaiting_submission | 待提交 | 尚未实际提交 |
| submitted / receipt_received | 已提交 / 已收到提交回执 | 分别有实际提交或回执记录，不由生成 ZIP 推断 |
| 没有足够依据 | 尚未记录 / 尚未确认 | 不猜测通过、失败、用户批准或队友最新进展 |

任务“已完成”只能修饰这项任务，不能外推到全题、论文或比赛。结果检查记录、AI 评价、队员判断和赛事方确认分别表述。

## 按钮与提示

- 查看：打开建模工作台、刷新进展、查看结论依据、查看检查报告。
- 思考与续接：比较建模方案、复制讨论提纲、复制续接说明。复制不等于已发送。
- 本地意见：建模意见 → 保存意见 / 请 AI 分析 → 意见记录与回复。只保存时明确“尚未发送给 AI”。
- 进度分享：导出项目进展简报。导出不等于发给队友。
- 诊断：导出诊断记录。内部编号、版本值、哈希仅保留在明确的诊断或原文入口。
- 错误：说明发生了什么、输入是否保留、可以怎样恢复。例如“项目已有新变化，未自动重发。请查看最新进展，确认后再次提交。”

命名采用“对象 + 动作”或具体内容名。普通界面不用“对象注册”“权威投影”“CAS”“接入执行器”等实现词；开发文档保留准确技术名称。未知错误可展开原文，不能为了全中文而猜测错误原因。用户原话、引用、历史报告和原始数据保持原样。

## 维护与应用范围

- 此表是唯一产品术语表；README、AI 引导和工作台内容规则链接到这里，避免各存一份互相漂移的定义。
- 新文案先确定对象、动作、接受者和证据范围，再选用名称；不能靠统一叫“完成”掩盖状态差异。
- 内部 API、类型名、路径、命令参数和既有项目数据保持不变。无需数据迁移。
- 历史发行包、验收截图、原始反馈和已交付推广包不追溯改字；新版文案随下次发行同步，不能声称旧截图已经使用新名称。
- Preview 对外写“公测预览版”；尚未公开发布的候选写“公测预览候选版”。版本号原样保留，名称调整不代表已经发布或所有功能已经验收。
