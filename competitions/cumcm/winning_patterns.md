# CUMCM 高质量论文模式（winning_patterns）

> 这是写作与复核启发，不是官方评分细则，也不能预测奖项。样本清单记录了 91 份公开论文来源，其中 59 份满足当前文本提取条件；这里引用的分位数只描述这 59 份可提取子集。每年比赛以同目录 `current_rules.md` 链接的官方文件为准。

## 1. 摘要是一张结果地图

高信息密度摘要通常同时回答五件事：

1. 解决什么问题，关键约束是什么；
2. 每个子问题采用什么模型或算法；
3. 得到哪些可核验的数值结果；
4. 怎样验证误差、敏感性或稳健性；
5. 模型的适用边界与可推广场景是什么。

它们可以写成三至五段，不必机械凑段。归档的 59 份可提取样本中，摘要中文字符数 p25 / p50 / p75 为 748 / 992 / 1146；PDF 解析会带来误差，因此这些值只用于发现“过短、无结果”或“过长、失去摘要功能”等异常。

摘要中的每个数值都应能在正文或结果文件中追溯。没有真实计算结果时，宁可标记待补，也不要使用占位数字。

## 2. 目录展示推理链

一个稳妥的主线是：

```text
摘要 → 问题重述 → 问题分析 → 假设与符号
     → 分问题建模、求解与解释 → 验证/稳健性
     → 模型评价与推广 → 参考文献 → 附录
```

章节数量本身不产生质量。真正要检查的是每一问是否完成“题意 → 数学对象 → 求解 → 结果 → 现实解释”的闭环，以及后续问题是否正确使用上游结果。

电子论文的格式要求会变化。当前基线要求摘要作为第一页、不放目录、不暴露身份，正文不超过 30 页；提交前必须重新核对 `current_rules.md` 与当年官方通知。

## 3. 图表服务于证据，而不是密度

一张图或表至少应承担一种职责：

- 解释数据与异常处理；
- 展示算法、依赖或决策流程；
- 报告核心结果与对比基线；
- 说明误差、敏感性或失稳边界。

标题、坐标、单位、图例和数据来源应自洽，正文先说明“为什么看它”，再解释“它证明了什么”。59 份样本的图数 p25 / p50 / p75 为 5 / 8 / 20，表数为 4 / 6 / 9；题型差异很大，不应把这些分位数变成配额。

## 4. 模型名称必须对应真实设计

名称的作用是让读者快速识别结构，而不是用“改进”“混合”制造创新感。建议使用：

```text
<关键机制或约束> + <核心模型> + <求解/校正方法>
```

例如，只有在确实引入动态权重时才写“动态权重”；只有在两个模型的输入、损失或决策真正耦合时才写“混合”。正文应明确说明与标准方法相比改了什么、为何需要、代价是什么。

## 5. 子问题之间保留可追踪的复用链

当题目逻辑存在依赖时，后续问题要显式引用上游产物：参数估计、最优方案、预测值、约束边界或评价权重。每次复用至少写清：

- 来源问题与结果版本；
- 进入本问的变量或文件；
- 单位、索引和转换；
- 上游误差怎样传播到本问。

若各问本来相互独立，不应为了“看起来完整”强行制造依赖。

## 6. 假设要有依据，也要能回检

每条假设应附一种可核验依据：题目条件、附件数据观察、物理或业务规律、参考文献。模型和结果完成后再回检：假设是否被数据推翻、是否限制结论、放宽后结果是否显著变化。

符号表与假设表必须和正文同步。符号首次出现时说明含义与单位，同一符号不要跨子问题换义。

## 7. 验证设计与模型风险相匹配

不要默认所有问题都需要同一种灵敏度分析。按模型风险选择手段：

- 预测问题：留出验证、交叉验证、基线比较、误差分层；
- 优化问题：可行性检查、上下界、替代求解器或小规模精确解；
- 评价问题：权重扰动、排序稳定性、一致性检查；
- 仿真问题：随机种子、多次重复、置信区间、极端场景；
- 关键参数耦合明显时：再使用多变量联合扰动或全局敏感性方法。

结论应量化“在哪个范围内保持稳定、越过什么边界会失效”，并解释该范围为什么符合实际。

## 8. 模型评价要写边界与代价

有效的局限性说明包含四部分：观察到的限制、受影响的结论、可替代的方法、改进所需的数据或计算代价。不要虚构“预计提升 3%”之类未经实验支持的幅度。

推广同样要写适配步骤：哪些参数可复用，哪些数据必须重采，哪些约束会改变。只写“可推广到其他领域”不构成证据。

## 9. 参考文献、代码与 AI 披露形成证据链

参考文献没有通用的最低条数。数量应由实际使用决定：模型选择、参数来源、假设依据和对比方法都要在正文对应位置引用，列表与正文一一匹配，并采用当年要求的格式。

附录与支撑材料只保留复现所需的代码、数据说明和关键中间结果；删除调试日志、凭据、个人与学校信息。代码开头注明对应正文小节、入口命令、随机种子和主要依赖。

使用 AI 工具时，按 `current_rules.md` 的当年要求进行文内标注、参考文献登记和使用详情记录；不要等终稿时凭记忆补写。

## 10. 怎样使用样本观察

- `empirical.json`：59 份可提取样本的结构化观察值；91 是来源总数。
- `empirical_notes.md`：同一批观察的人读说明与提取限制。
- `distilled_structures.md`：从观察值提炼的结构提示。
- `anti_patterns.md`：终稿检查项，不是扣分公式。
- `paper_skeleton.md`：可替换占位符的写作骨架。

先用样本分布发现异常，再回到题意、真实结果和官方规则做判断。分位数是参照物，不是把不同题目压成同一篇论文的模板。
