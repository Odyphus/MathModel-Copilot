# 电工杯 Phrase Bank (SEED v0.2)

> 工程语境中文写作示例，当前为手工整理的 seed，并非真实获奖语料统计。L1 critic 应检查工程量、来源和适用边界，不按句式或锚点命中数判定通过。

---

## 1. 摘要信息功能（可合并或拆分）

### 背景段
- "随着 {新能源 / 电网 / 储能} 的快速发展, {核心问题} 已成为 {电力系统 / 能源行业} 的关键挑战。"
- "针对 {题目情境}, 本文研究了 {核心子问题}, 并提出了 {方法名称}。"

### 方法段
- "本文建立了基于 {模型类} 的 {命名变体} 模型, 综合考虑了 {因素 1}、{因素 2} 与 {因素 3}。"
- "采用 {算法} 求解，并用 {与主要风险匹配的验证方法} 检查 {具体指标}; 其适用条件为 {条件}。"

### 结果段 (含工程数值)
- "在 {场景 1} 下, 优化方案使 {指标} 降低 {百分比}%, 从 {基线值} 降至 {新值} (工程单位)。"
- "灵敏度分析表明, {关键参数} 在 ±{percent}% 扰动下, 系统稳定性保持在 {阈值} 之上。"

### 工程建议段
- "基于 {结果与约束证据}，建议 {实施主体} 采取 {具体动作}; 在 {假设与场景} 下预计影响为 {量化结果与单位}。"

---

## 2. 引言 / 问题重述

- "近年来, {领域} 受到广泛关注, 其核心挑战在于 {挑战}。"
- "现有研究主要采用 {传统方法}, 但当 {条件} 时存在 {局限}。"
- "相对 {已定义基线或现行方案}，本文实际加入 {机制/约束}; 其影响由 {对照或验证证据} 支持。"

## 3. 假设与符号

- "为简化分析, 本文做如下假设, 其工程合理性见 §X。"
- "假设 1: {内容}; 依据 {物理 / 工程 / 历史数据} 支撑。"

## 4. 数据预处理

- "原始数据包含 {N} 条记录, 时间跨度 {时间段}, 采样频率 {频率}。"
- "采用 {方法与参数} 处理缺失值 (缺失率 {ratio}%); 根据 {设备边界/统计诊断/业务规则} 标记异常记录 ({count} 条)，并说明保留或剔除的影响。"
- "预处理后数据时序曲线见图 X, 统计描述见表 Y。"

## 5. 模型建立

- "设 {变量} ∈ {域} 表示 {物理含义, 单位 kW/kWh/...}。"
- "目标函数为 {经济 / 物理 / 安全} 指标 {表达式}。"
- "约束条件来自 {电网 / 设备 / 调度规则}: 等式约束 (1)-(3); 不等式约束 (4)-(7)。"

## 6. 求解与算法

- "采用 {求解器 / 启发式 / 强化学习} 求解, 算法步骤见算法 1。"
- "在 {硬件配置} 上, 单次求解耗时 {秒}, 满足在线调度需求。"
- "收敛性由 {收敛指标} 在 {代数} 内降至 {阈值} 验证。"

## 7. 灵敏度 / 鲁棒性

- "根据 {历史波动/测量误差/工程边界} 对 {关键参数组} 联合扰动，采用 {采样方法与样本量依据}; 输出指标 {metric} 的 {区间类型} 为 [{lower}, {upper}]。"
- "在有依据的工程参数范围内，系统 {稳定性指标} 的变化为 {结果}; 超出 {边界} 后结论不再成立。"

## 8. 工程实施 / 落地

- "该方案在 {省/市} 电网试点部署需 {资源}, 预计 {年限} 年回本。"
- "工程上可分阶段实施: 第一阶段 {内容}; 第二阶段 {内容}。"
- "落地风险主要来自 {风险点}, 可通过 {应对} 缓解。"

## 9. 结论与建议

- "本文针对 {核心问题} 建立了 {方法名}, 主要结论如下:"
- "面向 {实施主体}，建议在 {触发条件} 下采取 {可操作动作}; 依据为 {结果表/情景分析}，预期效益与代价分别为 {量化值}。"
- "本研究的局限性在于 {局限}; 未来工作可在 {方向} 进一步深入。"

## 10. 工程术语标准化

| 推荐 | 避免 |
|------|------|
| 渗透率 / 出力 / 弃风率 | 占比 / 输出 / 浪费率 |
| 调峰 / 调频 / 备用 | 控制 / 平衡 |
| 负荷曲线 / 时序 | 数据 / 序列 |
| 节点电压 / 潮流 | 电压 / 流量 |
| 储能配比 | 储能比例 |

## 11. 信息与证据链检查 (L1 critic)

| Stage 8 部分 | 检查问题 |
|--------------|----------|
| 摘要 | 任务、方法、工程量结果与边界是否对应正文；是否只写确有证据的建议？ |
| 引言 | 工程背景和研究缺口是否有可靠来源，而非只用“受到关注”等套话？ |
| 数据预处理 | 每次填补、标记或剔除是否记录规则、数量及对结果的影响？ |
| 模型 | 变量是否带单位，目标与约束是否对应设备、调度或安全规则？ |
| 验证与稳健性 | 参数范围是否来自数据或工程边界，结论是否报告误差和失效条件？ |
| 工程实施 | 实施主体、动作、资源、代价和风险是否由当前结果支持？ |
| 结论与建议 | 每条建议能否回指结果表或情景分析；没有证据时是否删除？ |
