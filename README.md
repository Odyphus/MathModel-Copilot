## 下载后，发给 AI 安装就能开始

**第一步：点击上面的按钮，下载 Skill 压缩包。**

**第二步：把压缩包发给你的 AI，并说：**

> 请帮我安装这个 MathModel Copilot Skill。按照包内说明，只安装一个主入口；如果已有旧版，先保留原安装。安装完成后告诉我怎么开始使用。

**第三步：把数学建模题目和附件发给 AI，开始练习。**

> 请用 MathModel Copilot 带我做这道题。先透彻分析题目，再按每一问比较可行的建模思路。讲解要通俗，但也要说清专业模型名称、数学结构、算法和取舍。论文由我主导。

还没有题目，也可以直接说：**“进入教学模式，带我了解这个 Skill 的功能。”** 教学随时可进入，也可只学一项，不限首次使用。

需要能读取本机文件、执行程序并使用 Skill 的 AI 工具，例如已配置相关能力的 Codex；基础环境需要 Python 3.10+，缺少时让 AI 先检查并说明。仅能聊天、不能安装 Skill 或操作本地文件的网页对话，无法直接完成安装。

当前为 **v0.3.0-preview.1**。仓库暂为私有，下载需登录有访问权限的 GitHub 账号；暂未开放给所有人。按钮直接指向运行 ZIP，不是开发源码包。更多环境说明见 [安装文档](docs/INSTALL.md)。

## 产品理念

现有很多数学建模 AI 工具，关注的是“怎样让 AI 替人完成更多工作”，例如自动选模型、自动写代码、自动生成论文。但是实际上，一场真正的数学建模比赛，并不是一个可以被简单自动化的任务。

一场比赛持续数天，需要不断地理解问题、提出想法、修改模型、运行实验、判断结果，并由三名队员和 AI 持续协作。真正重要的判断、创造和取舍，最终仍然需要人的参与。

因此，MathModel Copilot 的目标不是替代人，而是帮助人和 AI 更好地一起完成比赛。

它首先提供一套基本的工作流和脚手架，让 Agent 能够知道一场数学建模比赛应该如何推进，并让持续参与从审题、建模、实验验证，到论文与最终交付的全过程。

在此之上，它希望把人的精力，从版本、文件、状态和重复检查等琐事中释放出来，留给真正需要人的地方——理解、判断、创造与取舍。

同时，它希望建立一条持续而高效的信息流：人的想法可以随时传递给 AI，而 AI 当前推进到了哪一步，也可以通过可视化的面板清晰地反馈给人；不同队员之间，则能够始终围绕同一套最新的信息和结果顺畅协作。

总结一下，MathModel Copilot的目标，不是让 AI 取代人，而是让人和 AI 真正成为一个能够持续协作的建模团队。

## 有哪些功能

下面按实际使用顺序介绍。每项都对应 [本机实测手册](docs/LOCAL_FEATURE_TRIAL.md)中的验收卡：可以看到怎样操作、应该得到什么、怎样判断是否好用。功能介绍不是“所有场景均已验收”的承诺；当前实测范围在文末单独说明。

### 1. 随时学习：不知道怎么用，就进入教学模式

Skill 会在首次完整使用时简短介绍工作方式，并在需要时提示相关能力。你可以随时进入或退出教学，也可以只了解审题、模型比较、结果依据、论文、接力等某一项。工作台的“使用帮助”与对话使用同一套 12 项功能目录。

**你会得到：**功能解释、适用场景、可直接发给 AI 的使用示例。退出教学后回到原任务，不重新初始化项目。

> 进入教学模式，只教我怎样比较模型和检查结果。讲完回到刚才的题目。

![教学模式的实际页面](https://github.com/Odyphus/MathModel-Copilot/blob/main/docs/media/help-catalog-1440.png?raw=true)

*0.3 实际浏览器截图，背景为隔离的合成验收项目。页面复制请求后仍需发给当前 AI，不假装已经唤醒聊天。*

### 2. 完整审题：先把问题看懂，再动手计算

沿用十阶段工作流，先梳理全题目标、输入数据、要求输出、单位、约束以及各问之间的依赖，再逐问推进。把容易遗漏的小要求拆成可检查的项目，而不是只用“第几问完成了”笼统概括。

**你会得到：**题目要求清单、附件用途说明、问间依赖和当前缺口。创建了任务、写好了代码，都不会自动把要求变成“已核验”。

> 先带我完整分析题目：每问要解决什么、用哪些数据、交什么结果，哪些地方容易漏？先不要直接给最终答案。

### 3. 候选模型比较：让人有依据地选择

对于存在真实替代路线的问题，引导 AI 比较候选方案。解释要从直觉落实到**专业模型名称 → 数学结构 → 求解算法 → 验证方法 → 取舍与当前状态**。例如线性规划（LP）、混合整数线性规划（MILP）、动态规划各自适用的条件，要结合题目说明，不能为了显得专业硬贴名称。

**你会得到：**变量、目标或控制方程、关键假设、数据需求、计算成本和局限的对照，以及选择理由。模型与数值算法分开讲；只有一种合理路线时说明原因，不凑数。

> 给这一问两个真正可比较的候选思路。先用通俗语言解释，再写出专业名称、数学结构、算法和适用条件，让我判断怎么选。

### 4. 题意与假设管理：把分歧说清楚

将歧义、不同解释、建模假设和影响范围登记下来。关键假设变动后，可追踪受影响的模型和结果；未处理的中高影响歧义会阻止相关合同冻结与运行，避免 AI 悄悄替团队作出重大选择。

**你会得到：**待判断事项、候选解释、选择记录及后续需要验证的假设。接受一种解释是建模决定，不等于它已经得到数学验证。

> 这句话有没有两种解释？分别会怎样改变模型？把关键假设列出来，区分题目给定和我们额外引入的条件。

### 5. 真实运行与独立检查：把“算过了”落实到记录

按已登记的模型、参数、数据和代码实际执行 Python 程序，保留当次输入、环境、输出、日志和结束情况；再执行预先声明的独立检查器，核对约束、指标、容差或交付格式。

**你会得到：**可追溯的运行结果与检查记录。写出程序、运行成功、通过检查是不同状态；失败、依赖缺失、跳过和未执行分别保留。

> 按我们选定的方案实际运行，先说明检查标准，再核对结果。告诉我哪些通过了、哪些还没有依据。

### 6. 结果依据与变更影响：改了条件，旧结果不能继续冒充有效

将题目要求、运行、检查、结果、结论与论文章节关联起来。模型、参数、数据或代码发生变化后，重新观察依赖状态，提示哪些成果需要重算、哪些结论和章节需要重检；保留旧版本，不静默覆盖历史。

**你会得到：**某个数字从哪里来、当前是否还能使用，以及改动影响了什么。检查有依据，不代表所有语义、因果解释或模型适用性都已被证明。

> 把这个参数改掉后，哪些结果和论文内容受到影响？先列出来，再按已授权方案复算。不要自动把旧论文标为通过。

### 7. 建模工作台：不用翻长聊天，也能看清当前进展

本机页面提供**项目总览、各问进展、成果与依据、论文准备**四个入口，显示当前工作、变化摘要、待判断事项和下一步。普通页面优先中文，专业模型名与科学单位保留，内部编号不占据主要位置。

**你会得到：**固定、可复用的页面。换题无需重新生成网站；可见时每 15 秒读取本机进展，不额外调用 AI。首次完整练习在环境允许时由 AI 主动启动并尝试展示，你也可以说“不用页面”。

> 打开建模工作台，先告诉我离开之后变化了什么，现在最需要我判断什么。

默认只读。可选启用“建模意见”后可以记录意见；保存、AI 回复、队员采用、数学核验仍是四个不同事实。实验性的 Codex CLI 分析入口不保证唤醒当前桌面会话。详见 [交互说明](docs/LOCAL_INTERACTION.md)。

### 8. 论文、摘要与图表辅助：让材料为人的论证服务

按各问整理可用结果、论证提纲、来源和缺口。图表建议先回答“它支持哪个结论”，再说明与模型、结果的适配度、信息表达和可读性；不以 3D、渐变或装饰判断图表质量。摘要辅助围绕实际问题、方法、关键结果和结论展开。

**你会得到：**材料清单、提纲、图表建议、批注与检查结果；需要时再请求局部段落或摘要候选。改稿另存，论文的组织、取舍和定稿由人主导。

材料预检能检查已登记 CSV 表格或绘图输入与小问、运行、参数的绑定，以及缺列、重复表头和非有限数值。它不证明成图数据映射和自然语言论证正确；优秀摘要目前只有接入模板，没有已经整理好的案例库。

> 整理这一问的写作材料和论证提纲。哪些结论值得用图解释？推荐图型并说明理由，列出摘要可用的结果和仍缺的依据。

### 9. 队内接力与可选 Git：减少“你用的是哪个版本”

根据建模、编程、写作角色生成任务交接说明，包含当前模型与结果、累计变化、未完成事项和下一步。写入时检查版本冲突，区分收到资料、采用决定和完成核验。需要时可用 Git 交换草稿、提案和文件，但合并不能绕过权威状态检查。

**你会得到：**换人、换会话时可读取的交接材料。未启用 Git 也能在本机使用；目前没有跨电脑的三人实时云端同步。

> 给编程和写作队友分别整理交接说明。明确哪些成果可以用，哪些需要重检，不要把收到材料说成已经采用。

### 10. 赛事适配、复核与交付检查：逐项检查有没有漏

保留 CUMCM、MCM/ICM、电工杯赛事包，并提供 generic/custom 起点。结合当届官方规则检查论文、附件、AI 使用说明和交付材料；Critic / Red Team 从假设、约束、证据和论证缺口等角度组织复核。

**你会得到：**问题清单和具体材料的检查结果。赛事规则要按年份核对；材料齐全、具备待提交条件和真正提交是不同事实，历史练习不能被标成正式可提交。

> 按当前赛事要求检查遗漏，再从反方角度审查我们的假设和结论。把机器能检查的、需要人工判断的分别列出。

### 11. 本地复盘与再次续接：回来以后不用重新回忆全过程

取得你的选择后，记录本项目或本次工作的必要过程，收尾时生成本地 Markdown 复盘：目标、取舍、困难、已有结果、未完成事项和下一步。原文片段、用户报告和 AI 转述分开，没有采集到的上下文明确说明。

**你会得到：**下次可以重新读取的过程记录。续接先用旧复盘理解来由，再检查当前项目和文件；旧成功不覆盖现在的失效结果。关闭宿主后没有后台监听保证，自动收尾由正在执行 Skill 的 AI 完成。

> 本项目可以记录关键取舍和问题。结束时整理本地复盘，下次先检查当前状态再继续；不要对外分享。

### 12. 个人偏好与经验：留下有用的方法，不继承旧题的答案

明确保存讲解偏好，以及你选定的可复用经验。经验带来源、标签和适用条件，后续只读取少量相关项；来源失效或撤回后不继续使用，可以查看、修改和删除。

**你会得到：**减少重复说明的个人记录。它独立于队伍的建模权威状态，不自动随 Git 分享，也不会把上一道题的假设默认为新题条件。

> 以后保留专业术语并解释清楚。把这次我选中的单位换算经验保存下来，只在适用的题目里参考。

### 13. 有上下文的使用反馈：让问题容易被理解和复现

围绕你的目标、预期、实际表现、必要过程、纠正和后续处理生成反馈草稿，区分程序事实、用户感受和 AI 推断。可以编辑、脱敏预览、导出 Markdown；配置仓库并授权后，使用发送器创建 GitHub Issue，并核对是否送达。

**你会得到：**不用重述整段经历的反馈材料。本地留存和对外分享分别选择，默认不分享；限定自动分享也必须事先明确范围和次数，且不发送题目、结果、聊天片段或自由文本。

> 把刚才的问题和必要过程整理成使用反馈，标明缺少什么证据。脱敏后先给我看完整正文，再决定是否上传。

真实 Issue 创建与回读仍待单独验收，当前不宣称远端反馈通道已经全部跑通。详见 [使用反馈说明](docs/USAGE_FEEDBACK.md)。

## 看一次真实运行

内置合成交通示例采用**流体排队模型 + 有限策略枚举**。程序实际计算，独立检查器核对结果，然后把依据接到要求和示例章节上；它不需要官方题面或现场数据。

此前 v0.2 Preview 2 的实机演示留下了这样一条链路：

| 操作 | 实际观察 |
|---|---|
| 首次计算并核验 | 5/5 项示例要求有当前有效依据 |
| 将假定通行能力从 0.8 改为 0.7 vehicle/s，暂不重算 | 覆盖变为 0/5，旧结果和章节需要重检 |
| 重新计算、检查并关联结果 | 恢复 5/5；旧论文段落仍需重检，不被自动改写或通过 |

## 怎样在自己的电脑上逐项体验

建议一次建立独立练习项目，分三段体验：**开始与选型 → 运行与变化 → 写作、接力与复盘**。不是每个功能重新找一道题，也不需要每一步都回复“继续”。

[本机实测手册](docs/LOCAL_FEATURE_TRIAL.md)为安装和上面 13 项功能分别给出操作、应看到的结果、检查方法与证据要求。程序能检查的由 AI 连续执行，你集中判断讲解是否透彻、候选是否真有差异、图表建议是否有意义、回来能否快速接上。

[本轮已经实际跑过什么、还有哪些卡待体验](docs/LOCAL_TRIAL_20261007.md)单独记录，避免把“测试方案写好了”当成“每个功能都验收了”。

想先自己运行示例，可在解压目录执行：

```sh
python scripts/copilot.py --workspace ../demo-project demo
python scripts/copilot.py --workspace ../demo-project dashboard --port 8765
```

演示项目目录须为空或不存在。浏览器打开终端给出的本机地址，保留服务运行；第二次只重开工作台，不重复创建演示。macOS/Linux 可用 `python3`。基础示例和工作台使用 Python 标准库，不需要 Node 或前端构建；处理实际赛题所需依赖另行检查。

## 当前版本做到哪里

核心流程、状态与证据管理、可复用工作台、教学、个人记录和反馈发送器已实现。建模方法解释、图表建议、写作辅助属于对执行 AI 的工作要求，实际质量仍受模型与上下文影响；不能用程序测试通过代替用户体验验收。

目前还需要补验：真实 GitHub 反馈送达、兼容宿主的自然语言自动收尾与新会话续接、新用户首次体验、macOS，以及依赖历史附件或 TeX 环境的部分流程。页面直接唤醒真实 AI 也没有成功验收保证。完整论文定稿与人工终审由人负责。
