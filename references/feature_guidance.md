# 功能发现与首次体验

本文件指导 AI 在首次完整练习、使用者询问功能或当前工作适合某项能力时提供帮助。产品名称按 [术语规范](../docs/PRODUCT_LANGUAGE.md)；实际操作沿用 [统一执行协议](copilot_runtime.md)，不新增项目状态或另一套工作流。

0.3 增加 [教学、复盘与使用反馈执行协议](experience_runtime.md)：先读个人设置，随时使用 `experience tutorial` 进入完整或单项教学；首次邀请可以跳过，关闭邀请仍能手动进入。功能事实表由 `experience catalog` 与工作台共用。已有记录许可时，关键节点及时留存、本段结束自动复盘、下次实际读回续接；没有许可则不额外采集。

## 首次介绍：简短说明后直接做事

首次开始完整比赛或练习时，结合实际任务，用三四句话说明能怎样配合。已有具体题目就直接开始全题分析，不让用户先选一遍功能菜单；不能用介绍替代审题。

可参考以下表达，按当前材料和授权调整，不照读模板：

> 我会先梳理各问要求，再比较可行的建模方案；普通计算与检查按你的授权推进，重要取舍会说明依据。建模工作台可以查看当前进展、结果依据和下一步，环境允许时我会把它打开。之后你也可以直接说“比较方案”“看看哪些结果需要重检”或“给队友整理交接说明”；论文由你主导，我辅助整理材料和检查遗漏。

如果用户只是询问功能，先回答再按需给使用入口。如果只要某问方案、解释一个模型或修改某段材料，则完成该范围，最多补一句相关能力，不为引导另建项目或启动页面。维护技能包本身时也不进入参赛引导。

## 建模工作台：默认介绍，有条件展示

工作台由随包固定的 `dashboard/` 页面读取项目记录；题目变化、刷新或再次使用都不要求重新设计或生成页面。

首次完整项目按以下规则处理：

1. 已成功初始化或续接真实项目、完成本轮首次状态读取后，环境能运行 Python 本机服务且未被用户拒绝时，主动启动**只读**工作台。不要等用户知道 `dashboard` 命令；也不要等全题做完才展示。页面暂时内容少时说明正在审题，不编造展示数据。
2. 使用宿主允许的会话进程运行下述既有命令，不让长期服务阻塞建模任务。`--port 0` 由系统分配空闲端口；以实际返回的 `dashboard_url` 为准。已有服务时先核对项目身份与可访问性，复用同一项目的服务，不猜端口、不终止其他服务。

   ```console
   python <skill>/scripts/copilot.py --workspace <project> dashboard --port 0
   ```

3. 用 `X-Copilot-Read: 1` 请求实际地址的 `/api/snapshot`，核对 `project_id` 与当前项目的 `view` 一致、读取成功且 `read_only=true`。本机端口存在或返回首页不代表读到了正确项目。内部编号只用于核对，不作为面向用户的名称。
4. 宿主有页面打开能力时调用该能力展示；只有真实成功才说“已打开”。工具仅返回排队时说“已请求打开”；能访问但不能自动打开时给用户可点击的实际地址。远程执行环境的 `127.0.0.1` 不一定对用户设备可达，不能当成已展示；仅使用已有、已授权的预览能力，不自行部署到公网。
5. 缺少 Python、无法保持进程、权限受限或页面不可达时，说明这项限制并继续对话中的建模与进展总结；不反复尝试或把页面作为审题门槛。用户说“不用页面”后，在本会话及能读到该偏好的后续工作中尊重其选择，不反复推荐。

默认不带 `--interactive`、`--assistant-codex` 或 `--git`。用户希望在页面记录想法时，再说明并启用本地建模意见；实际请求 AI 分析涉及已有账户、额度和权限，按 [本地交互说明](../docs/LOCAL_INTERACTION.md) 处理。页面读取不调用模型，意见保存、AI 回复、采用与检查分别表达。

这里规定的是 **AI 使用 Skill 时的引导行为**。`init` 和 `demo` 命令自身不自动启动浏览器，`dashboard` 命令只运行本机服务。不要把新增指令描述为所有 AI 工具已经稳定执行过的自动打开功能。

## 在需要的时候介绍功能

在正常成果说明中嵌入“当前需要 → 相关能力 → 具体产物或动作”。每次优先一项最有用的提示，不另列长功能菜单；已经在授权范围内的必要工作直接做，不反复问“要不要”。参考入口按需读取，不一次加载全表文件。

| 实际情境 | 主动做什么或提示什么 | 可用入口与边界 |
|---|---|---|
| 首次读完整题面 | 展示逐问题目要求清单，说明它会帮助检查漏问、漏输出 | `requirements` / Stage 2；先真实登记，不能将读题算作完成 |
| 准备选模型、有真实替代思路 | 比较候选的专业名称、数学结构、算法、前提与代价，让用户看懂取舍 | Stage 3；比较在 AI 对话中完成，不承诺页面已有比较操作，不硬凑方案数量 |
| 对题意或假设有不同解释 | 展示解释选项及对后续模型的影响，留下采用理由 | `interpretation` / `interpretation-review`；普通自治范围内继续推进，确需人判断时集中说明 |
| 首次真实计算结束 | 给出结果和已执行的检查范围，指出工作台哪里可以追溯依据 | `run` / `validate` / 工作台“成果与依据”；未检查不能说已核验 |
| 改了参数、数据或代码 | 主动说明哪些结论需要重算或重检，并按授权处理 | `status` / `impact`；这属于基本正确性，不是可忽略的产品推荐 |
| 结果需要呈现或解释 | 推荐能支持特定结论的图、表或文字，说明适配理由和来源 | `paper_assistance.md`；有必要才制图，不为体验功能凑图 |
| 用户暂时离开或说记不清进度 | 从当前记录概括上次目标、有效结果、待办和下一步；需要分享时提示项目进展简报 | `status` / `context` / `report`；用户明确要求保存简报就导出，不要求重新讲一遍背景 |
| 用户想在页面留下想法 | 说明建模意见可先保存在本机，以及可选分析或复制续接说明的区别 | `dashboard --interactive`；不默认开启模型调用，不把复制或保存当作 AI 已回复 |
| 开始写论文或整理摘要 | 主动给出可用材料、模型主线、关键结果、局限和缺项，再按请求辅助局部文字 | Stage 8 / `paper_assistance.md`；不主动生成整篇论文，不称优秀摘要库已经齐备 |
| 需要队友接手 | 优先生成任务交接说明；只有确实需要多机文件交接时介绍可选 Git | `context` / `docs/GIT_COLLABORATION.md`；导出不等于送达，Git 合并不等于采用，不擅自推送 |
| 准备打包提交 | 提示提交材料检查与剩余人工事项，按授权运行实际检查 | Stage 9 / `docs/DELIVERY.md`；打包、待提交、已提交和取得回执分别确认 |
| 一次体验结束、放弃或卡住 | 已获准时自动保存本次复盘；选取必要过程整理使用反馈，补齐“预期、实际、影响”和缺失说明 | `experience recap` / `usage-feedback`；分享单独授权，发送并回读一致才是送达；缺仓库或账号仍保留本机草稿 |

例如，参数修改后可以说：“容量调整后，上一版费用和对应图表需要重新检查。我会先确认受影响的结果，再按当前参数重跑；工作台会显示哪些旧材料暂时不能继续引用。”应以本次真实观察和授权为准，不能把例句里的动作或结果套成已发生的事实。

## 让用户随时找到能力

用户说“你还能帮我做什么”“有哪些功能”“带我体验一下”时，按目标组织回答：

- **开始建模**：梳理题意、检查资料、比较候选模型。
- **把结果做可信**：实际运行、独立检查、查看结论依据、追踪变更影响。
- **继续工作或找队友接手**：建模工作台、项目进展简报、任务交接说明、可选 Git。
- **准备论文和交付**：图表建议、写作材料、摘要辅助、来源与材料检查。

这份能力地图与 `experience catalog` 的专题保持一致，工作台“使用帮助”可随时阅读。始终标明当前环境不可用、尚未验收或仍在规划的能力。默认先展开与当前任务最相关的一组，用户要完整列表时再展开全部。

## 短体验与提示频率

用户明确要快速体验但没有选题时，可在独立空目录使用现有 `demo`，展示“查看要求 → 看一次真实运行与检查 → 追溯结果 → 改一个参数观察旧结果失效 → 重算并说明仍未完成的论文/提交事项”。`demo` 本身只负责演示计算链，后面的改参数、重算通过原有接口执行，不能声称一条命令已经做完全部体验。用户只要看看界面时不要擅自修改其项目，可使用已获准的独立示例。

完整体验以理解核心价值为准，不要求为了打卡而启用 Git、连接付费 AI、写整篇论文或实际提交比赛。

- 首次介绍只做一次；重复调用同一能力、重复刷新或换一个小问时不重复介绍。
- 用户已用过相关功能时直接继续，只有出现新限制或新机会才解释。
- 同一会话内明确拒绝的可选提示不再重复；新会话先读 `experience settings` 中已明确保存的邀请和提示偏好。工作台“不再提示”是本浏览器偏好，和对话端个人设置各有范围；未保存的选择不承诺跨宿主继承。
- 对安全使用当前结果必需的失效、缺问和提交阻碍仍要说明；用户不想听功能介绍，不等于隐藏这些事实。
- 不能为了记录“介绍过某功能”而改写权威状态、引入额外模型调用或制造采用/完成记录。
