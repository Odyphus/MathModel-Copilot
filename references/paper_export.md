# 已核验章节导出：文字保真、原生对象、实际读回

使用现有 `paper source 0.1` 合同，按登记的章节顺序装配。原稿由作者决定；导出器不代写、不改正文，不从历史总结恢复已失效的数字。需要当前有效的 PaperSection、Claim、图表及来源；导出期间来源或项目版本变化时停止。

```text
python scripts/copilot.py --workspace <项目目录> paper-export --expected-revision <当前版本> --contract paper/source_contract.json --output paper/本次论文.docx
```

加 `--pdf paper/本次论文.pdf` 可选择本机 LibreOffice 或 Windows Word 转换。Word 正在使用时不关闭或隐藏用户文档。输出路径只能在项目内，文件必须新建；PDF 后端失败时保留已读回审计的 Word 文件，失败不算 PDF 验收通过。

正文、表格、图片及简单公式生成真正的 Word 对象。当前原生公式仅支持无上下标的表达式和简单分式；复杂公式明确拒绝，不以文字或图片冒充可编辑公式。编号/图表引用复用现有章节结构绑定；参考资料只保留原稿已有内容，不自动补写文献或声称完成引文核验。

表格按正文数字与列标题分配宽度，保留原始小数精度，必要时将表格字号调整到 9—11 磅。若仍不能在当前纵向页面清晰容纳，则停止并提示调整表结构或另选版式；不会为了排版自动舍入数值。实际渲染后的阅读效果仍须检查。

保存后按现有来源审计器读回 DOCX，比较有序正文、表格单元格、公式结构与绑定图片，再登记 generated ArtifactRecord。源稿、检查报告和来源合同随成果绑定，参数/结果/章节改动会使旧导出成果失效。

`source_readback_passed` 只代表来源读回检查。实际渲染、公式显示、页面溢出、赛事模板及人工定稿仍须另行检查；本命令不自动宣称 submission_ready，也不自动冻结或发送作品。工作台“论文准备”分别显示这些状态。
